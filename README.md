# KGExplorer

KGExplorer is a Vue + D3.js + Flask prototype for a minimal paper-style knowledge graph exploration interface.

## Project Structure

```text
KGExplorer/
  frontend/   Vue + Vite + D3.js
  backend/    Python + Flask API
```

## Frontend

```bash
cd frontend
npm install
npm run dev
```

The Vue app runs at `http://127.0.0.1:5173`.

## Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

The Flask API runs at `http://127.0.0.1:5001`.

## Guqin Curated Data

Raw OCR, images, and triplet workbooks under `backend/data/raw` are immutable.
The application reads a reproducible curated layer with evidence-audit states:

```bash
python backend/scripts/rebuild_case1.py
python backend/scripts/build_guqin_evidence_table.py
python backend/scripts/build_guqin_curated.py
```

Generated exploration data:

```text
backend/data/curated/guqin/explorer.json
backend/data/processed/guqin_evidence/
```

Useful API routes:

```text
GET /api/case-data/guqin
GET /api/guqin/explorer?q=&source=&slot=&readiness=
GET /api/guqin/conflicts/<conflict_id>
GET /api/guqin/records/<record_id>
GET /api/text/<record_id>
GET /api/images/<record_id>
```

The UI's Corpus Explorer filters the graph, hierarchy, candidate queue, source
matrix, and evidence tray. `P1_expert_review` candidates can be adjudicated;
`P2_data_cleanup` and `P3_alignment_review` candidates expose their audit flags
and keep terminal decisions disabled until the data issue is resolved.

## LLM Semantic Judgment (Case 3 · News)

The rule-based judge is an exact match on normalized values, so semantically
equivalent variants surface as `overlap`/`differ`. Case 3 adds an optional
DeepSeek-based semantic judgment layer. It is **additive**: rule statuses are
never overwritten (rule colors stay as the fallback), and Cases 1/2 are
untouched.

1. Configure the key (see `backend/.env.example`):

   ```bash
   export DEEPSEEK_API_KEY=sk-...                    # required
   export LLM_MODEL=deepseek-chat                    # optional
   export LLM_BASE_URL=https://api.deepseek.com      # optional
   ```

2. Generate verdicts with the offline batch script (resumable sidecar):

   ```bash
   python backend/scripts/run_llm_judge_news.py --dry-run
   python backend/scripts/run_llm_judge_news.py --limit 5
   python backend/scripts/run_llm_judge_news.py          # full run, resumes
   ```

   Output: `backend/data/news/v7/processed/llm_verdicts.json`. The comparisons
   file itself stays untouched (it is generated by the external gdnews backend
   and replaced in place).
   Only comparisons whose rule class is A (differ) or B (overlap) are judged;
   consensus and single-source slots keep rule colors.

3. In the UI (Case 3 · News) use the toolbar 判定方法 toggle to switch between
   规则 and 大模型. Slots with a verdict are marked ✦ in the adjudication
   worklist and show the LLM reason in the adjudication panel. Verdict
   mapping: consistent → green (consensus), conflict → red (differ),
   uncertain/missing → rule color fallback.

Useful API routes:

```text
GET  /api/news/llm-verdicts     sidecar verdicts consumed by the frontend
POST /api/llm/judge             online single-slot judgment (JSON body)
```
